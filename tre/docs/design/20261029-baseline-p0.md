# Baseline P0 corrections (2026-10-29)

Authorized scope: implement the six P0 items agreed with the user. Do not add routing,
drain, change prediction windows, recalibrate V/mu, change replica formulas, or deploy.
Base: aibrix main 633b080f. Independent branch fix/baseline-p0-20261029.

1. PreServe arr retains pending work; ft starts the decode look-ahead contribution.
   Queued work cannot accrue generated tokens or justify underload shrink. Existing
   wall-time/ITL advancement after ft is retained as a documented approximation.
   Gateway ft now ignores role-only, keepalive and usage frames; SSE prefixes are bounded.
2. Gateway req_id + pod identifies an execution attempt. client_id links the sidecar's
   retry/continuation. Starting a reissue ends its previous engine attempt, even if the
   parent HTTP stream remains open forwarding the child. Late parent ft/done cannot
   affect the child. Arr/ft preceding the first snapshot of a woken pod are buffered;
   remove the old absence-tick timestamp cutoff. Known ended attempt IDs are retained
   only for the existing bounded retention interval.
3. Replay t0 is the first arrival's Redis stream timestamp, passed explicitly. Predictor
   error RNG and trace seed remain separate. Pre-marker arrivals are bounded and backfilled
   into Tier-1 when the marker arrives. Lost bootstrap history keeps failing explicitly.
   The runner rejects pre-load markers and stops its loadgen child if marking fails.
4. TokenScale degraded input counts prohibit shrink; measured-input arrivals can prove a
   lower bound on scale-up demand. Character-count estimates do not prove expansion.
5. History generation reads each Real model's own preceding 25*30s source interval,
   with its frozen keep fraction and the identical SplitMix64 byte-offset sampling.
   It never reads the test request file to estimate rate or mean length. The suite's
   lengths already include chat template tokens; apply its explicit input floor once.
   Synthetic past: extend the initial baseline, or the specified sinusoid into negative
   time. Record sources, hashes, ranges, sample counts, and input units. Dataset stays
   outside git. Frozen replay artifacts are not modified.
6. score_pilot and tre_eval share a single strict scorer. success_strict alone determines
   completion. Failed partial output is truncated; failure before output is failed;
   old rows without strict evidence are unknown, never silently successful. Complete
   requests alone populate latency percentiles. All scored requests remain in V_req's
   denominator. Duration >=149s is diagnostic, not proof a normally completed request
   was cut. The quick first-run check and completed-rate series follow the same rule.
