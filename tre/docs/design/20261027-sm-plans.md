## 1. Problem and decisions

Each SM write request (`PUT /v2/models/{m}/target` v2.py:620, `PUT /v2/bindings/{b}/power` v2.py:1049,
`POST /v2/transfers` v2.py:4626) covers one model, one binding or one donor→receiver pair, and
takes the global writer lock once. Inside one request the sleeps and wakes already run in parallel
(`SleepPrimitive._parallel` sleep_primitive.py:1164, `_run_wakes` v2.py:3951). A decision that sleeps
3 models and wakes 2 therefore costs ~5 serial holds (~7.5 s) instead of ~3 s. The controller adds
its own serialization: a SafeScale commit is per-pod `PUT /power` (action_queue.py:1852-1869), then
per receiver a `GET /v2/state` (`_resolve_target` AQ:1164), a second GET (sm_client.py:231-241) and
`PUT /target`, and the lock is released between the donor sleep and the receiver wake.

Architect decisions (fixed; see the task brief): (1) `POST /v2/plans`, one plan = sleep items +
wake items under ONE hold, `/transfers` retired; (2) keep the whole lock, no new intermediate state;
(3) absolute targets (wake: at least, sleep: at most) resolved by the SM under the lock, named pods
allowed for sleeps; (4) two waves; (5) all invariants kept; (6) batched observed refresh + fixed
lock budget; (7) `/target` and `/power` become wrappers; (8) controller: one decision → one plan,
no batching timer, no redundant GET, no-op fix; (9) TRE controller and baseline controllers move
to the new endpoint.

Correction to the brief: there is **no transfer journal** to generalize. `/transfers` has none by
design (wholelock §6: "没有 transfer journal，也不续接"); a crash is settled per binding by the sleep
and wake journals. Plans keep exactly that (§6).

## 3. API: `POST /v2/plans`

Pydantic (v2.py, next to `TargetRequest` :6910):

```python
class PlanDonor(BaseModel):          # relay allowance of a wake item
    model: str
    max: int = Field(ge=1)           # donor replicas this item may take (= TransferIntent.count)
    sleep_path: str = "urgent"

class PlanSleepItem(BaseModel):
    model: str
    pods: list[str] | None = None    # exact serve ids (SafeScale probe pods, ShrinkForSlot)
    at_most: int | None = Field(None, ge=0)   # model-level shrink; exactly one of pods / at_most
    sleep_path: str                  # required, EXTERNAL_SLEEP_PATHS (v2.py:7244)
    reason: str = ""                 # caller label, echoed in results / events

class PlanWakeItem(BaseModel):
    model: str
    at_least: int | None = Field(None, ge=0)  # absolute grow-only target
    pods: list[str] | None = None    # exact serve ids (binding wake, awake_ctl); one of at_least / pods
    hints: list[str] = []
    avoid_gpus: list[str] = []
    donors: list[PlanDonor] = []
    reason: str = ""

class PlanRequest(BaseModel):
    plan_id: str | None = None       # echoed; SM makes "pl-<12 hex>" when absent
    sleeps: list[PlanSleepItem] = []
    wakes: list[PlanWakeItem] = []
```

Validation (400, nothing done): at least one item; known models; each model in at most ONE item
(a donor model of a wake item counts as that model's sleep side and may not appear elsewhere);
`sleep_path` external; named pods must belong to the item's model; item count ≤ number of registry
models. One model, one direction, one item: floor and cap are computed per model once, and the
controller already never emits two power actions for one model in one submit (§5.2).

Response (200 / 409 `partial`):

```
{plan_id, version, status: done|partial|noop|failed,
 sleeps: [{index, model, reason, sleep_path, status: done|noop|clamped|refused|failed,
           taken, clamped_by_floor, floor?, outcomes: [<sleep-primitive outcome per pod>], error?}],
 wakes:  [{index, model, reason, status: done|partial|noop|refused|failed,
           awake_before, awake_after,
           woke: [{serve_id, binding_id, node, gpu_ids, wave: 1|2,
                   source: free|plan_sleep|donor|hint, hinted, donor_binding_ids, compensating_sleep?}],
           donors_slept: [{model, binding_id, serve_id, sleep_path, status}],
           unfilled, refusals: [<WakeConflict.body>], skipped: {}, error?}],
 phases_ms: {select, wave1, wave2, settle, refresh, total}}
```

HTTP status: 200 when anything changed or every item was a no-op / floor clamp; 409 `partial`
(structured, full body, like `TransferFailed` v2.py:6750) when nothing changed and at least one item
was refused or failed; pre-execution 409 `writer_busy` / `routable_unknown` and 400 as today.
Per-item `retriable` mirrors the old per-endpoint classification (`RETRIABLE_STATUSES`,
`NOT_EXECUTED_CODES` sm_client.py:16-37) so controller retry logic keeps its inputs.

**Observability kept stable.**

## 4. Executor

### 4.1 Selection (pure, new `tre_sm/ops/plan.py`, generalizing `ops/transfer.py`)

Inputs read once under the lock: store bindings, leases, sleep/wake journals (`busy_binding_ids`),
floor + routable set per sleep model (`_floor_check` v2.py:5698), cap per wake model
(`scale_max_replicas`), topology / placement policy, and ONE resident probe round over every GPU
that is either a wake candidate's or held by a possible plan sleep (`_probe_pods_on_gpus` v2.py:5415).

1. **Sleep items → set S.** Named pods: awake ones join S (hidden ones too: a SafeScale commit
   sleeps its hidden probe pod); already asleep = `noop` (records desired "sleeping", as `/power`
   does at v2.py:1076); a journaled wake → refused `wake_in_progress` (as `/power`), no pod IP →
   refused `pod_not_found`. Floor: the item's whole pod set
   is checked once; violation → item `refused floor_violation` (named pods are never clamped, as
   `/power` today), nothing of that model hidden. `at_most`: the existing shrink order (hidden first,
   then `release_order`, v2.py:943-972), clamped at the floor (`_clamp_sleep_plan_to_floor`
   v2.py:5748), `clamped_by_floor` in the result.
2. **Planning view P** = books with S counted asleep and S's leases ignored.
3. **Wake items, in request order.** `need = at_least − awake` (≤ 0 → `noop`, donors untouched).
   a. Candidates = sleeping bindings of the model whose GPUs are either free (wake blocker None on
      the real books → **wave 1**) or held only by S members (blocker None on P → **wave 2**,
      `depends_on` = those S members). Pick with `_wake_pick` (v2.py:7294) on P, hints first: the
      same placement policy that picks today when `/target` runs after a SafeScale donor slept.
   b. Still short and `donors` given: `select_transfer_pairs` (transfer.py) per donor on P with
      `count ≤ max`, the donor floor and the receiver budget; its donors join S (with the donor's
      `sleep_path`), its receivers join wave 2. Free GPUs are used before extra donors
      (deviation from `/transfers`, which never looked at free GPUs: fewer interrupted requests).
   c. Named wakes (`pods`): each must be feasible as in (a); infeasible → refusal.
   Every pick updates P (cumulative cap, floor headroom and GPU use across items).
4. **TP2.** A wave-2 receiver's GPUs must ALL be held by S members (the transfer rule
   `SKIP_UNCOVERED_GPU`, kept; a mix of free GPU + plan donor is skipped, not guessed). Its wake
   starts only when every S member on its GPUs is confirmed asleep.
5. **Third resident.** Any other resident of a wave-2 receiver's GPUs must read asleep in the probe
   round (`_transfer_veto` v2.py:4720, generalized); wave-1 candidates go through the normal wake
   gate (gpu-truth or the same probe round, `_shared_resident_probe` v2.py:5399).

### 4.2 Execution (one `_writer("plan")`)

```
lock → validate → load books, ONE Pod LIST, ONE probe round, routable views
     → (routable unknown for a sleep model: 409 routable_unknown, nothing hidden)
select (pure) → prepare wave-1 tickets (lease, wake journal, desired intent; v2.py:3435)
wave 1: thread A = SleepPrimitive.sleep(all of S)   ‖   thread B = _run_wakes(wave-1 tickets)
        join → record sleep outcomes (lease released only for "slept") → commit wave-1 wakes (no settle yet)
wave 2: tickets whose depends_on all "slept" → prepare (gate "plan_probe") → _run_wakes → commit
        dependents of a failed / unconfirmed / rolled-back donor: not prepared, refusal "donor_sleep_failed"
settle: ONE /is_sleeping round + ONE compensating sleep for every failed ticket of both waves
refresh: ONE Pod LIST + parallel probes for every touched binding (decision 6)
response, operation note, plan_done event
```

Changes to existing code: `_commit_wakes` (v2.py:4020) is split into commit and settle so both waves
share one deferred settlement (`_settle_failed_wakes` v2.py:4154); `_refresh_observed` (v2.py:3263)
becomes batched and is called once per hold — today the wake commit calls it **per ticket**
(v2.py:4068: N serial LISTs) and `observe_bindings` (reconcile.py:360) probes pods **serially**, both
outside the budget. Thread A and B must not save the store concurrently: the sleep primitive only
does hide/ack/sleep/confirm in thread A; all store / lease / desired writes happen on the request
thread after the join. Thread A runs one primitive call per sleep path (items may name different
paths; the floor guard and the journal record the path), in parallel. Wakes per wave ≤ GPU count;
the wake executor gets max(`WAKE_WORKERS` 8, the topology's GPU count) workers so a wave never
queues (implemented as sizing instead of a startup assert).

### 4.3 Wrappers (decision 7)

`/target`, `/power`, v1 `/scale_service`, `/wake_up` take the lock with their old operation kind,
build a one-item plan from the **fresh** books (exact `/target` decides grow vs shrink under the
lock), call `_execute_plan_locked`, and map the item result back to the legacy response and status
(`taken`, `clamped_by_floor`, `picked`, `unfilled`, `refusals`, `TargetPartial` 409 for an exact
growth v2.py:770, `at_bindings_limit` for v1 `/wake_up`, 409 `lease_conflict wake_in_progress` for a
journaled binding v2.py:1067). Concrete semantics that do not map one-to-one:

- **Cold create** (`plan["create"]`, v2.py:666-667 / 717-745 → `_create_and_wake_runtime_binding`
  v2.py:5980): the executor never creates. A growth past the existing bindings becomes `unfilled`
  with refusal `no_binding`. Safe today: `max_awake_replicas ≤ max_replicas` (registry.py:1324) and
  `tre_models.sh up` deploys every binding, so the planner's `_plan_create_capacity`
  (planner.py:2003) cannot ask for one; missing Deployments are fleet repair's job. Q3.
- **No-runtime mode** (`_apply_model_target_plan` v2.py:881, `_put_binding_power_unlocked`
  v2.py:1233; used by many unit tests): the executor has a books-only actuation step (same
  validation and selection, outcomes written to the store) instead of keeping a second planner.
- Not blockers: cap (`_ensure_wake_within_cap`), floor clamp vs refuse, `within_bindings`, `hints`,
  `avoid_gpus` all map to item fields.

Implemented (step 3; cold create removal approved by the architect): the cap check, `within_bindings`,
the `at_least` no-op, `/power`'s journaled-wake 409 and its already-asleep no-op stay as wrapper
prechecks; `/power` without the runtime keeps `_put_binding_power_unlocked` (a store write, no
planner). Desired state of a wrapper plan follows the outcome per binding (woken → awake, slept →
sleeping, a failed wake restored) instead of rewriting every binding of the model
(`_set_model_desired_target`); only the books-only path and an unchanged `/target` still rewrite
the model's desired target. The cold-start tests that went through `/target` now drive the
remaining cold start (the defrag destination, `_start_gated_binding`) directly; the seven
`/target` create tests of test_api_v2.py are replaced by one `no_binding` test.

Deleted afterwards: `_plan_model_target` growth part, `_prepare_target_wakes`, `transfer()`,
`_select_transfer`, `_transfer_*`, `_Transfer*`, `TransferRequest`, `/transfers`
(v2.py:4589-5018 and :7208), `K8S_CALLS_TRANSFER_SELECT`, `worst_case_transfer_lock_s`.

## 5. Controller

### 5.1 Client
`sm_client.post_plan(request) -> {"ok", "response", status fields}`, slow timeout
(`api_call_timeout_s`). Removed: `scale_model_to`, `scale_model_hinted`, `transfer`, and the
GET precheck (sm_client.py:231-241). `scale_model` / `set_binding_power` go away once every
dispatch builds plans.

### 5.2 One decision → one plan (no timer)
A decision = the actions of ONE `ActionQueue.submit()` call (tick.py:338, one planning pass;
safescale_task.py:224/568). Nothing waits for more actions.

- After the existing accept/drop loop (AQ:387-452), the accepted re-plannable power actions of
  that submit (`ScaleAction`, `TransferIntent`, pods-named shrinks; not SafeScale one-shot actions,
  which keep their own plan and retries) are fused, in submit order, into one `PlanBatch` queued
  item (`models`/`resources` = union). **Architect change (2026-10-27, implemented): fusion only
  across DIFFERENT models, strictly 1:1** - each action becomes exactly one item (`+k` → wake
  `at_least = awake + k`; a relay `D→R count c` → wake of R `at_least = awake_R + pairs`,
  `donors=[{D, c}]`, and D counts as used by that item; a shrink → one sleep item). An action that
  touches a model an earlier member already uses (the same receiver twice, a shared donor, a shrink
  and a grow of one model - possible through the rescue path, which skips the inflight check at
  AQ:415) starts the next `PlanBatch`; those serialize through their shared models as today. Several
  actions of one model are NOT merged into one item (that needs a planner-side change and its own
  evaluation; simplicity first). So the motivating CRITICAL rescue (`+k`, `D1→R`, `D2→R` on one R)
  still costs one plan per action of R, but every other model of the decision joins the first plan.
  A batch takes the queue position of its first member; a member never jumps over another accepted
  action (e.g. a hide) of one of its models. A rescue that replaces a pending fairness action drops
  only that member from a pending batch.
- Hide / unhide / defrag stay separate queued actions (not power).
- **Absolute targets**: one `GET /v2/state` per plan dispatch resolves every relative item
  (`awake + delta`, cap, and the shrink serving floor of sm_client.py:213); the resolved plan is
  frozen. An item with `at_least ≤ awake` (or `at_most ≥ awake`) is dropped locally; a plan with no
  item left sends nothing (decision 8).
- Members are re-plannable: no retry, as today (`_retry_safe` AQ:2069, ONE_SHOT_LOOPS AQ:37).
  The observe re-read stays right before the one POST (AQ:834).

### 5.3 Mapping results back
Each member action still gets its own `DispatchResult` from its own item result (1:1, no split
attribution needed), so `_stamp_changes` (AQ:1561), `_record_done` (AQ:1872), `_note_rescue_result`,
`_note_relay_hold`, `_record_transfer_done`, events and stats keep their meaning. A relay's item:
`done` = receivers woken (any source: the SM may use a free GPU first), `taken` = its
`donors_slept`. Whole-plan refusals (409 `writer_busy`, `routable_unknown`, 400) give every member
`not_executed`. A transport error / timeout gives every member "unknown" (both stamp directions),
as for `/transfers` today (`_transfer_changed` AQ:2037).

### 5.4 SafeScale commit = one plan per attempt
Attempt = sleep item `pods = commit.pods` (path `safescale_commit`) unless `donor_done`, plus one
wake item per pending `ReceiverTarget` with its frozen absolute `target` (resolved once by the
plan's GET, AQ:1164 logic kept). Result: donor slept → `donor_done`; `unconfirmed` outcomes →
`unconfirmed_pods`; receivers done / filled in part → removed (same as `_receiver_result` AQ:1822);
retriable receiver refusals stay for the retry. The retry loop, revalidation before every retry
(`_revalidated_commit` AQ:1184), stale-evidence check (AQ:951), observe conversion (AQ:989),
rescue preemption (AQ:1349) and unhide after a failed donor (AQ:935) are unchanged. A replayed plan
is harmless: named pods already asleep are `noop`, `at_least` already met is `noop`.

Two visible semantic changes (architect ack needed, see report):
- A receiver whose wake lands on a free GPU (wave 1) now wakes even when the donor sleep fails;
  today receivers are sent only after the donor slept (AQ:1104-1119). Dependents of the donor's GPUs
  still never wake.
- Observe entered after the POST cannot stop the receivers any more (AQ:1128-1151 goes away); the
  SM completes the plan, as `/transfers` already does (AQ:1494-1506).

### 5.5 No-op bug fix
Today `scale_model_to` answers a precheck no-op as ok (sm_client.py:241) and `/target at_least`
answers an SM-side no-op with `actions: []`; `_receiver_result` (AQ:1822) returns the ok result
unchanged when `unfilled == 0`, so `_stamp_changes` stamps routable/view "up" and `_record_done`
sets `_last_done = "up"` although nothing woke. Fix: a member whose item woke nothing gets
`woke_none = True` (also for a local no-op, which makes no SM call); `_record_done` skips
`woke_none` like `_stamp_changes` already does (AQ:1592).

## 6. Lock-hold bound and failure semantics

Every phase runs its items in parallel and every Kubernetes step is one batched call, so the bound
does not grow with the item count (guarded by the call-budget test). New
`ServiceManagerConfig.worst_case_plan_lock_s()` replaces `worst_case_transfer_lock_s`
(registry.py:1171) and is the only term of `worst_case_lock_hold_s` (wrappers run the executor):

| Term | Formula | Default |
|---|---|---|
| select | `probe_timeout_s` + `K8S_CALLS_PLAN_SELECT`(3: pods, routable view, residents) × 7 | 26 |
| wave 1 | max(sleep core `worst_case_sleep_lock_s` 108, wake core = probe + `wake.call_timeout_s` + 2·probe + `K8S_CALLS_WAKE`·7 + margin = 55) | 108 |
| wave 2 | wake core | 55 |
| settle | one compensating sleep `worst_case_sleep_lock_s` | 108 |
| refresh | `K8S_CALLS_REFRESH`(1) × 7 + `probe_timeout_s` | 12 |
| margin | `io_margin_s` | 2 |
| **total** | | **311 s** |

Client worst case = 30 + 311 + 2 = 343 s < `api_call_timeout_s` 360 (validated at startup,
registry.py:1925). SIGTERM wait = 313 s > `terminationGracePeriodSeconds` 300
(overlays/tre-v2/service-manager.yaml:29) → raise it to **330**; the guard
deploy/tests/test_kustomize_overlays.py:92 enforces it. The baseline scaler's `TRE_BL_SM_TIMEOUT_S`
default 300 (baselines/config.py:113) is already below today's 322 s worst case → set it from
`api_call_timeout_s` (360). The deferred single settlement is what keeps the bound at 311 (two
separate compensating sleeps would give 419). No item-count limit is needed beyond the validation
rule (≤ one item per model) and wave size ≤ GPUs ≤ `WAKE_WORKERS`.

| Case | SM | Controller |
|---|---|---|
| lock wait > 30 s | 409 `writer_busy`, nothing done | members `not_executed`; SafeScale retried with backoff + revalidation; others dropped, next tick re-plans |
| routable view unreadable | 409 `routable_unknown` before any hide | same |
| bad request | 400 | non-retriable |
| named sleep below floor | item `refused floor_violation`; its dependents unselected; rest proceeds | commit stays retriable (as `/power` 409 today) |
| `at_most` below floor | clamped, `clamped_by_floor`, `taken` may be 0 | `scale_clamped_by_floor` event |
| donor `/sleep` rolled back | pod unhidden only after the awake re-check (wholelock invariant 3); dependents refused `donor_sleep_failed` | commit retry / unhide as today |
| donor unconfirmed | stays hidden, lease kept, journal `sleep_unconfirmed`; dependents refused | `unconfirmed_pods`, never unhidden |
| wake fails (either wave) | settled at the end: asleep → lease released; awake → compensating sleep; no answer → journal + lease kept (`uncertain`) | `wake_refused` / `partial` events |
| partial fill | item `partial`, `unfilled`, `refusals` | `receiver_short` / `partial` events, re-plan |
| fence lost (Redis) | stops at the next fence check; journals settle | timeout / 5xx → unknown |
| SM crash mid-plan | lease expires; next writer marks the op superseded (`supersede_stale_operations` v2.py:2004); sleep / wake journal entries (now tagged `plan_id`) settle by physical state; a donor may stay asleep with no receiver ("slept once for nothing", as for `/transfers`) | transport error → unknown, stamps both ways, next tick re-plans; SafeScale retry resends an idempotent plan |
| client timeout, SM continues | plan completes | unknown; replay is a no-op |

## 7. Baselines

`Dispatcher` (baselines/sm_client.py:447) keeps one worker per model and one call in flight per
model, and sends one-item plans: up = wake `at_least`, down = sleep `at_most` with
`TRE_BL_ABORT_SLEEP_PATH`. The stepped scale-up (start+1..target, :545-570) is dropped: commit
43444853 added it because the SM refused a whole multi-replica growth when one wake was blocked;
the SM fills growths best effort since 10-06 (`_finish_growth` v2.py:746), so one `at_least` call
wakes the same set in one hold. `reached` = `awake_after` of the item. Option (Q1): one plan per
tick across models, which gives the baselines the same batching TRE gets.
